Las funciones

¿Qué hacen YEAR, MONTH y DAY?

Extraen una parte específica de una fecha. Devuelven un número entero.

YEAR(fecha) → número

Devuelve el año.
YEAR('2026-08-12') → 2026

MONTH(fecha) → número

Devuelve el mes (1-12).
MONTH('2026-08-12') → 8

DAY(fecha) → número

Devuelve el día (1-31).
DAY('2026-08-12') → 12

Sintaxis general
SELECT
  YEAR(reading_timestamp),  -- extrae el año
  MONTH(reading_timestamp), -- extrae el mes (1-12)
  DAY(reading_timestamp)    -- extrae el día (1-31)
FROM telemetry_pzem;
Lógica condicional

¿Qué es CASE WHEN?

Es el equivalente en SQL de un if / else if / else en PHP. Evalúa condiciones en orden y devuelve el primer resultado que se cumple.

Estructura SQL
CASE
  WHEN condicion_1 THEN resultado_1
  WHEN condicion_2 THEN resultado_2
  WHEN condicion_3 THEN resultado_3
  ELSE resultado_default
END AS nombre_columna
Equivalente en PHP
if (condicion_1) {
    resultado_1;
} elseif (condicion_2) {
    resultado_2;
} elseif (condicion_3) {
    resultado_3;
} else {
    resultado_default;
}

Necesidad identificada

El cliente necesita ver el consumo promedio por día clasificado como bajo, moderado o alto para detectar días de uso anormal del rack.

¿Cómo se resuelve hoy?

En exportar_datos.php el filtro por fechas se hace en PHP comparando strings. La clasificación no existe — habría que hacerla recorriendo el CSV manualmente.

Consulta 1 — Simple

Usando YEAR, MONTH y DAY

Extraemos cada parte de la fecha de las mediciones reales del PDU.

La consulta
SELECT
  reading_timestamp,
  YEAR(reading_timestamp)  AS año,
  MONTH(reading_timestamp) AS mes,
  DAY(reading_timestamp)   AS dia,
  voltage_v,
  power_w
FROM telemetry_pzem
WHERE codigo_pdu = 'BD-DEMO-G9'
ORDER BY reading_timestamp DESC
LIMIT 5;

Consulta 2 — Final

YEAR + MONTH + DAY + CASE WHEN

SELECT
  DAY(reading_timestamp)   AS dia,
  MONTH(reading_timestamp) AS mes,
  YEAR(reading_timestamp)  AS año,
  ROUND(AVG(power_w), 2)   AS potencia_promedio_w,
  ROUND(AVG(voltage_v), 2)  AS voltaje_promedio_v,
  CASE
    WHEN AVG(power_w) < 100
      THEN 'Consumo bajo'
    WHEN AVG(power_w) BETWEEN 100 AND 500
      THEN 'Consumo moderado'
    WHEN AVG(power_w) > 500
      THEN 'Consumo alto'
    ELSE 'Sin datos'
  END AS clasificacion_consumo
FROM telemetry_pzem
WHERE codigo_pdu = 'BD-DEMO-G9'
GROUP BY
  YEAR(reading_timestamp),
  MONTH(reading_timestamp),
  DAY(reading_timestamp)
ORDER BY año DESC, mes DESC, dia DESC;

YEAR, MONTH y DAY permiten agrupar por día sin importar la hora. CASE WHEN clasifica el resultado directamente en SQL — sin procesar nada en PHP.

Comparación

PHP vs SQL

Como se hace hoy — PHP
// exportar_datos.php
$desde = mysqli_real_escape_string(
  $conex, $_POST['desde']
);
$hasta = mysqli_real_escape_string(
  $conex, $_POST['hasta']
);
$sql = "SELECT * FROM telemetry_pzem
WHERE reading_timestamp
BETWEEN '$desde' AND '$hasta'";

El formato lo maneja PHP. La clasificación no existe — requeriría un if/else por cada fila.

vs
Con las funciones asignadas — SQL
SELECT *
FROM telemetry_pzem
WHERE
  YEAR(reading_timestamp)  = 2026
  AND MONTH(reading_timestamp)
    = 8
  AND DAY(reading_timestamp)
    BETWEEN 1 AND 12;

El filtro y la clasificación ocurren en el motor. PHP solo recibe el resultado final.

  • 📍Legibilidad: con YEAR/MONTH/DAY es más claro qué parte de la fecha se filtra. Con strings hay que conocer el formato exacto.
  • ⚡Rendimiento: SQL procesa el filtro en el motor de base de datos, sin traer todas las filas a PHP.
  • 🔧Flexibilidad: con CASE WHEN la clasificación vive en la consulta y se puede cambiar sin tocar el código PHP.
  • ⚠️Limitación: YEAR/MONTH/DAY no aprovechan índices sobre la columna de fecha, lo que puede ser más lento en tablas muy grandes.
